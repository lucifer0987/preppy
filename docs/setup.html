Setup checklist

The commands, in order, with nothing in between. For what each step does, why, and how to tell it worked, open architecture.html and read sections 12 to 16.

1First time, local

Terminal
node -v                 # needs v20 or newer
npm install
npm test                # 336 passing means the code is sound

Then in the Supabase dashboard:

  1. New project, named preppy-dev, nearest region.
  2. Apply the schema. Put the connection string from Settings → Database → Connection string → URI into .env.local as DATABASE_URL, password filled in, then npm run migrate. Use the direct connection on port 5432; a pooler URI on 6543 is transaction-mode and can trip the client.
    No connection string? npm run migrate -- --print prints the SQL to paste into the SQL Editor instead, in order.
    Either way you should end with eleven tables, each showing an RLS enabled badge.
  3. Authentication → Sign In / Providers → Email → turn Confirm email off.

Catching up a database made before migrations existed

If the schema was first applied by hand there is no schema_migrations table, so npm run migrate -- --status reports every file as pending, including ones already there. Expected. Run npm run migrate anyway — each file is written to be safe twice over, so the ones already applied pass through harmlessly and get recorded, and only the new ones change anything.

Step 3 is not optional

Skip it and every login is refused as unconfirmed — but the form only says "wrong username or password", so it looks like the password is wrong when it is not.

Back in the terminal:

Terminal
cp .env.example .env.local

# fill in three values from Supabase -> Settings -> API:
#   NEXT_PUBLIC_SUPABASE_URL        Project URL
#   NEXT_PUBLIC_SUPABASE_ANON_KEY   anon public
#   SUPABASE_SERVICE_ROLE_KEY       service_role  (secret)
# leave CRON_SECRET blank; it is only needed in production

npx tsx --env-file=.env.local scripts/preflight.ts local   # checks the keys
npm run seed            # prints passwords ONCE - copy them
npm run dev             # http://localhost:3000

The service_role key

It bypasses every access rule in the database. It belongs only in .env.local, which git already ignores. Never paste it anywhere else.

2Every day

Terminal
npm run dev

Restart it after editing .env.local — environment changes are not picked up while it runs. This is the most common thing to trip on.

3Publishing a paper

Terminal
npm run check -- my-paper.json          # validate before opening the app
npm run check -- my-paper.json --images ./img

Then in the app: Admin → Upload a paper → read the preview → Schedule. You choose its date and times on the schedule form; Admin → Nightly window only sets what is offered by default, and Admin → Paper pattern what a section holds when the file does not say. More than one paper can run in a day if their windows do not overlap. Copy format/sample.json as your starting point. The format is specified in architecture.html section 7.

4Shipping a change

Terminal
npm run build:prod      # preflight + typecheck + 336 tests + build
git add -A && git commit -m "what changed"
git push                 # Vercel deploys by itself

Never deploy between 10 PM and midnight

Somebody is probably mid-paper. Ship before 9 PM or after midnight.

5First time, production

A second Supabase project, preppy-prod. Never point your laptop at it.

  1. Same three dashboard steps as section 1, in the new project.
  2. npm run secret → copy the value.
  3. Push to GitHub, then import the repository into Vercel.
  4. In Vercel → Environment Variables, add four, all from preppy-prod:
    NameFrom
    NEXT_PUBLIC_SUPABASE_URLSettings → API → Project URL
    NEXT_PUBLIC_SUPABASE_ANON_KEYanon public
    SUPABASE_SERVICE_ROLE_KEYservice_role
    CRON_SECRETthe value from step 2
  5. Deploy. Then check Settings → Cron Jobs shows /api/cron/finalise at 30 19 * * * — that is 19:30 UTC, which is 01:00 IST.
  6. Seed production once:
    Terminal
    # .env.prod.local holds the PRODUCTION url + service-role key
npx tsx --env-file=.env.prod.local supabase/seed.ts
rm .env.prod.local

Before the first real paper night

architecture.html section 17 is a ten-minute walkthrough that exercises nearly every database query. Do it in daylight.

CommandWhat it does
npm run devDevelopment server, reloads as you edit

npm run typecheckTypes only, no build

npm run start:prodServes the production build

npm run seed -- --resetFresh passwords for everyone
npm run migrateApplies pending migrations
npm run migrate -- --statusWhat is applied, what is pending
npm run migrate -- --printPrints the pending SQL instead of running it
npm run secretA random string for CRON_SECRET

7Quick fixes

SymptomFix
"Not configured yet".env.local incomplete, or the server needs restarting
Login rejects a password you know is rightEmail confirmation is still on. Then npm run seed -- --reset
"Cannot build for production"Working as intended — it names the missing variable
Seeding errorsTables missing. Run npm run migrate
Nightly job did not runAdmin home → Finalise open attempts now
A paper will not deleteSomebody has a counted attempt on it. A trigger is refusing
Leaderboard missing a paperIt takes a paper in when that paper closes, 45 minutes after its last-entry time
Changed .env.local, nothing happenedRestart npm run dev

Three questions answer most problems:

  1. Which database am I talking to? Compare the URL in .env.local with the project name in Supabase.
  2. Did the schema apply? Table Editor: eleven tables, RLS badges.
  3. Does it fail without a database? npm test. If those pass, it is configuration, not logic.

Fuller troubleshooting in architecture.html section 18.
